# 云律 AI · 项目开发背景

> 本文档梳理项目开发过程中的关键信息，作为项目背景、答辩材料与后续迭代的参考。

## 一、项目概述

- **项目名**：云律 AI（代码工程 `cloud_music`）
- **一句话定位**：一款"懂情绪"的音乐播放器——用 AI 理解你的心情，用数据读懂你的品味
- **核心创新**：12 类情绪标签体系贯穿「AI 情绪点歌 → 歌曲情绪打标 → 每日推荐 → 歌词情绪曲线」，实现"心情驱动"的听歌方式
- **开发模式**：单人全栈，前后端一体化工程

## 二、技术选型与背景

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | Django 6.1（`django-admin startproject` 生成） | 8 大业务 app + 口令模块，全部置于 `apps/` 目录统一管理（`sys.path` 注入） |
| 前端 | 原生 JS（零框架），21+ 个模块化文件 | 按功能拆分 `player/lyrics/mood/voice/playlist/recommend/poster/report/eq/spectrum/theme/...` |
| 数据 | SQLite（业务数据）+ localStorage（收藏/最近播放/主题/断点） | `ListenRecord` 统一埋点，报告/排行榜/推荐/大屏共用 |
| AI | 智谱 GLM（`glm-4-flash` 免费模型） | 仅从环境变量 `ZHIPU_API_KEY` 读取，代码不写死 |
| 在线音乐 | iTunes（30s 试听）+ Jamendo（15万+ 完整版）+ SoundHelix（纯音乐） | `MusicSource` 抽象类插件式接入 |
| 依赖 | Django / mutagen / requests / Pillow / pypinyin / numpy | 极简依赖，零重型框架 |

## 三、功能演进历程（按开发阶段）

1. **链路验证期**：用 `scripts/gen_seed_music.py`（Python 合成旋律 WAV）验证「扫描 → 入库 → 播放流」基础链路
2. **真实曲库期**：个人收藏 498 首（461 MP3 + 37 FLAC，约 3.08GB）经 `scripts/copy_songs.py` 一键收集（自动去重、连歌词拷贝），按「歌手-歌名」规范命名、歌手分子目录
3. **核心功能期**（8 大板块顺序搭建）：`music` 曲库/播放 → `web` 前端 → `playlists` 歌单 → `lyrics` 歌词 → `recommend` 推荐 → `mood` AI 情绪点歌 → `posters` 海报 → `report` 报告
4. **播放增强期**：Canvas 频谱、10 段均衡器、定时关闭、断点续播记忆、Media Session 锁屏控制、封面自动生成
5. **视觉定制期**：CSS 变量驱动 7 套主题换肤（首屏无闪烁）、PWA 安装（manifest + 全套尺寸图标）
6. **数据与体验深化期**：实时数据大屏（`/dashboard/` Canvas 图表 + 4 秒轮询）、全屏情绪氛围背景（`ambient.js`）、键盘快捷键（`shortcuts.js`）、**歌词情绪曲线**（`lyric-curve.js`，逐句 AI 分析 + 本地兜底）

> 注：git 仓库已初始化但**尚无任何 commit**，开发过程未使用版本控制提交历史。

## 四、核心架构与设计决策

- **可插拔音乐源**：新增音乐源只需继承 `MusicSource` 注册一行，其他代码零改动（答辩重点创新点）
- **AI 服务隔离**：换 AI 模型只改 `apps/mood/ai_service.py`；推荐算法重写 `recommend/services.py` 接口不变
- **统一埋点**：播放自动上报 `ListenRecord`，支撑报告/排行榜/推荐/大屏四类消费方
- **静态缓存治理**：自定义 `static_ver` 模板标签，按文件 mtime 自动生成 `?v=` 版本号，改动代码无需手动刷缓存
- **外网分享适配**：`ALLOWED_HOSTS=["*"]` + `SECURE_PROXY_SSL_HEADER` + `CSRF_TRUSTED_ORIGINS`（内置 `*.vicp.fun`/`*.gicp.net`/`*.oray.fun` 通配），花生壳 HTTPS 穿透即插即用

## 五、数据资产与业务规模

- 本地曲库 498 首 / 3.08GB，152 份 `.lrc`（命中率约 30%，其余在线兜底）
- **498 首歌曲全部完成 AI 情绪打标**（12 类情绪标签）
- 12 类情绪标签：开心 / 难过 / 放松 / 充满活力 / 平静 / 浪漫 / 怀旧 / 专注 / 疲惫 / 愤怒 / 孤独 / 轻快
- 访问口令保护（默认 `yunlv888`，session 7 天免登）

## 六、关键技术难点与已修复问题

| 问题 | 解决方案 |
|---|---|
| 本地歌被"一刀切"标成 happy | `retag_songs` 命令按「歌名+歌手+歌词片段」AI 批量打标，无歌词/失败时关键词兜底 |
| 情绪推荐被 `genre=pop` 污染 | `emotions` 与 `tags` 合并查询；情绪标签优先、曲风仅补缺；演示曲不参与推荐 |
| 无本地歌词 | 在线两级兜底（网易云 → lrclib），成功后缓存 `.lrc`；兼容 UTF-8/GBK/GB18030 |
| AI 请求失败/断网 | 情绪点歌与情绪曲线均内置本地关键词规则降级，功能不中断 |
| 情绪曲线画布空白 | 面板隐藏时 `fit()` 将画布置 0×0 导致永久空白 → 加 0 尺寸保护 + 面板展开事件重绘 |
| 刷新丢失播放进度 | 播放记忆 localStorage 断点续播 |
| 语音环境嘈杂 | 快捷指令 chips（舒缓/欢快/动感/歌手/钢琴/随机）兜底 |

## 七、部署与分享形态

- 本地：`python manage.py runserver 8000`
- 局域网：`0.0.0.0:8000` + 口令
- 外网：花生壳 HTTPS 内网穿透（配置已内置）
- PWA：HTTPS/localhost 可安装桌面全屏运行（轻量版，无 Service Worker）
